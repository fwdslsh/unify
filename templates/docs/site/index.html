docs

Overview

The documentation home for your project — replace this. Everything you can read on this site is scaffolding: replace the words, keep the shape.

The guide

Guide pages live in site/guide/, one Markdown file each. Start one by copying site/_examples/guide-page.md there under the name you want in its address, editing the copy, and linking it from site/_includes/docnav.html, the sidebar. Nothing under _examples/ ships, and unify update never touches a file you copied. All pages lists every page the build publishes.

Documentation that already lives in a repository's docs/ folder needs no copying by hand: scripts/import-docs.mjs brings a folder of Markdown into the build at every run (see the README).

Which file is which

Four small files hold everything that names this site, and the layout includes each of them:

  • site/_includes/head.html: the title suffix, the description, the icon and the fonts;
  • site/_includes/nav.html: the masthead, with the wordmark and the links across the top;
  • site/_includes/docnav.html: the sidebar;
  • site/_includes/footer.html: the footer, which a page can replace by filling the footer slot.

To change the look, edit site/assets/theme.css: the custom properties the stylesheet reads, each at its default. unify.yaml names it in the keep: list under template:, so unify update never overwrites it.

How a page finds its layout

A guide page says nothing about a layout. unify looks for _layout.html in a page's own folder and then in each folder above it, so the layout at the source root wraps pages a level down without being asked. Put a _layout.html in site/guide/ and every page under it uses that one instead, written out in full, because layouts do not chain.

unify audit reports a page nothing links to, along with any page missing a title, a description, or a heading.
