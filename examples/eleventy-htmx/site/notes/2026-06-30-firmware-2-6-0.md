# Firmware 2.6.0

**The reference height is stored on the board.** Until now the height of the transducer
face above datum lived in the gateway's decoder, which meant the sensor reported a distance
and something else turned it into a level. Two consequences, both bad: a head swapped on the
bank silently inherited the wrong site's calibration, and a board with no calibration at all
reported a level that looked entirely plausible.

From 2.6.0 the board holds the reference, reports the level itself, and reports `0x8000`
when the reference is unset. Set it once with `level <metres>`; the procedure is in
[calibration](/docs/calibration.html).

**`dump` prints the whole configuration** — reference, radio region, DevEUI, sample window
and firmware version — as one block you can paste into a site record. It is the command we
should have written first.

One note for anyone templating the uplink downstream. Decoders that build a message from a
template need to escape their own delimiters when the payload description is passed through
them: a gateway template that writes `{{ level_mm }}` and `{% if dry %}` into its output is
a template inside a template, and every renderer in that chain gets a vote. Ours now emits
the field names as plain text and leaves the interpolation to whoever owns the last step.

Upgrading from 2.5.0 preserves nothing: the reference is new storage and starts unset, so
re-run `level` at every site after flashing.
