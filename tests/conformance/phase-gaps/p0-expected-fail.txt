WHY A RED HARNESS IS THE PHASE-0 PASS CONDITION — READ BEFORE "FIXING" ANYTHING
-------------------------------------------------------------------------------
This run is the harness's proof of detection. The v0.6 suite reported 93%
coverage and a green badge on a product whose golden path was broken
(docs/testing-strategy.md §1). Phase 0 lands the new authority: a harness
that drives the real CLI against the spec's own fixtures. Run against the
v0.6 engine it MUST be red — 81 of 86 cases fail below — because the engine
does not implement the v0.7.0 conformance spec. That red is the evidence the
harness can see the broken product the old suite blessed (migration-plan §3,
Phase 0 item 3, and Gate P0).

Therefore: any change that turns these cases green WITHOUT the v0.7 engine —
loosening the comparator in compare.mjs, widening its single whitespace
normalization, raising or removing the 30 s hang timeout or the 16 MB
runaway-output cap, softening diagnosticsExhaustive, or editing expected
trees to match observed output — is the exact failure mode this migration
exists to kill (strategy §1 M2/M3/M5, hygiene rule H5). The only legitimate
path from red to green is the Phase 1–4 engine work.
